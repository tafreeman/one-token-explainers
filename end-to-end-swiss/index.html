01

Read almost everything.

Pretraining starts as a stream of documents. Somewhere in it is a page that says “…the Eiffel Tower is in Paris.” Its “ Paris” is our token.

1.1Pool the sources

Crawled web pages, code, books, papers, math and many languages are pooled into one stream. Anthropic’s recent system cards describe the mix as public web data, licensed data, data from users who opted in, and data generated internally. They don’t publish proportions or totals.

Pretraining tokens

1.2Remove duplicates

Near-duplicate documents are found with MinHash signatures and dropped, so the model isn’t trained on the same text hundreds of times. Deduplication cuts memorised output and wasted compute.

sig  = minhash(shingles(doc))
keep = not lsh_index.has_near_duplicate(sig)
Method
MinHash + LSH
Lee et al., 2021

1.3Filter and mix

Classifiers drop spam, boilerplate, low-quality text and personal data. What’s left is reweighted so code, math and careful prose count for more than raw web text.

Mixture weights
Not published

02

Cut into tokens.

The model never sees letters. A byte-level tokenizer cuts text into pieces from a fixed vocabulary, and each piece becomes an integer ID.

2.1Byte-pair encoding

BPE starts from raw bytes and repeatedly merges the most frequent adjacent pair. Frequent words end up as one piece with their leading space attached, so “ Paris” is one token, not five letters.

ids = tokenizer.encode("is in Paris.")
# [382, 304, 12842, 13]   illustrative IDs
Algorithm
Byte-level BPE
Sennrich et al., 2016

2.2A fixed vocabulary

Every ID points at one row of a table the model learns. A bigger vocabulary means shorter sequences but a bigger table.

03

Predict the next one.

Claude Fable 5.2 · Published API — 1M-token contextDeepSeek‑V4‑Pro · Representative internals — figures marked *

Pretraining is one objective repeated trillions of times: given everything so far, put probability on the next token. The tower of layers you’ll meet again in stage 7 is built here.

3.1Forward, in parallel

A batch of sequences flows up the tower at once. A causal mask lets position n see only positions ≤ n, so every position in every sequence is its own prediction problem.

Total parameters

3.2Score the guess

After “…the Eiffel Tower is in”, the loss is the negative log of the probability given to “ Paris”. A multi-token-prediction head also predicts the token after that, which adds training signal at every position.

loss = cross_entropy(logits[:, :-1], ids[:, 1:]) + λ · mtp_loss
MTP depth
1 extra token*
DeepSeek‑V4‑Pro config

3.3Adjust every weight

Gradients flow back down the same layers and the optimizer moves every weight a little. DeepSeek‑V4 uses Muon for most matrices and AdamW for embeddings, the output head and norms. Pretraining uses FP8 mixed precision; quantization-aware training (QAT) produces FP4 expert weights for the released model.

04

Learn what good looks like.

Claude Fable 5.2 · Published API — no training recipeDeepSeek‑V4‑Pro · Representative internals — the recipe marked *

A pretrained model only continues text. Post-training turns the same tower into an assistant that follows instructions, uses tools and reasons toward answers it can check.

4.1Imitate

Supervised fine-tuning trains on curated demonstrations: conversations, tool calls, worked solutions. It uses the pretraining loss on much better data.

4.2Try, grade, reinforce

For a prompt with a checkable answer, the policy samples a group of attempts. Verifiers grade them: the tests pass, the final answer matches. Each score is compared with the group’s mean, so no separate value model is needed. Rewarding correct answers is also how a model learns to think before it answers.

A_i = (r_i − mean(r)) / std(r)
θ  ← θ + η · ∇ Σ_i A_i · log π_θ(attempt_i)
# simplified: GRPO also clips π_θ / π_old to 1 ± ε, PPO-style
Method
GRPO
Shao et al., 2024

05

Pass the gate.

Before a frontier model ships, it is tested for what it can do and for what it could be misused to do. After this gate the weights are frozen: everything training changed is now fixed, and no request will change it.

5.1Evaluate

Capability suites, agentic tasks and dangerous-capability evaluations (cyber, biology, autonomy) run on the final checkpoint. Anthropic publishes the results in a system card.

Framework
Responsible Scaling Policy
Anthropic

5.2Red-team, then set safeguards

Internal and external red teams hunt for jailbreaks and misuse. Under the Responsible Scaling Policy, higher capability requires stronger safeguards before deployment.

5.3Ship with classifiers

Deployed models run with safety classifiers beside them. On Fable 5.2 a classifier can end a reply with stop_reason: "refusal" and a stop_details category, such as cyber.

if (resp.stop_reason === "refusal")
  handle(resp.stop_details.category)

06

Your request arrives.

Months later you ask “What’s the weather in Paris right now?” with a get_weather tool attached. The API is stateless: every call carries the whole conversation. What the call builds is temporary, activations and a KV cache that end with the request, apart from any prefix the prompt cache keeps for reuse, 5 minutes by default.

07

One pass up the tower.

Claude Fable 5.2 · Published API — no internalsDeepSeek‑V4‑Pro · Representative internals — every figure, marked *

This is the engine. The token’s vector rides a residual stream up 61 layers; each layer reads from the stream and writes back to it. Anthropic doesn’t publish Claude’s internals, so this stage uses DeepSeek‑V4‑Pro’s published design as a representative frontier architecture.

7.1Look up a vector

The ID selects one row of the embedding table: a lookup, not a multiplication. Out comes a vector of 7,168 numbers, the start of the residual stream.

7.2Attend, sparsely

RMSNorm rescales a copy of the vector, then attention scores earlier positions, never later ones. To reach a million tokens, older context is compressed into blocks; a lightweight indexer picks the top-k blocks to read, plus a sliding window over the most recent tokens. Positions are encoded by rotating part of each query and key (RoPE).

Attention & KV mode, as drawn
V4-Pro at 1M: ≈10% of V3.2’s stored KV. CSA selects compressed history; HCA reads heavily compressed summaries; both keep a recent window* 
blocks = topk(indexer(q, kv_compressed), k=1024)
out    = attend(q, kv_compressed[blocks] ∪ kv[-128:])

7.3Route to 6 of 384 experts

A router scores 384 expert networks and keeps the top 6, and one shared expert always runs. Their outputs are weighted and summed. That’s why only 49B of the 1.6T parameters touch this token.

out = shared(x) + Σ_{j ∈ top6(router(x))} g_j · expert_j(x)

7.4Add back, sixty-one times

Each sub-block’s output is added back to the stream, and the layer repeats 61 times with different weights each time: a stack, not a loop. The drawing keeps one stream for clarity; DeepSeek‑V4 widens it into four parallel streams mixed by learned doubly-stochastic matrices (manifold-constrained hyper-connections)*.

for layer in layers:
    h = h + layer.attn(rmsnorm(h))
    h = h + layer.moe(rmsnorm(h))
Layers
61*
DeepSeek‑V4‑Pro config

7.5Score the vocabulary

A final RMSNorm and the LM head turn the vector into 129,280 logits, one per token, and softmax makes them probabilities. In the representative design, a small multi-token-prediction head also drafts the token after next, which serving can use to speculate*.

p = softmax(W_out · rmsnorm(h))     # 129,280 probabilities

08

Read the whole prompt at once.

Serving runs the frozen tower in two phases. Prefill pushes every prompt token up the tower in one parallel pass.

8.1Parallel and compute-bound

All prompt tokens go up together, as in training, but nothing is learned and nothing flows back. Large matrix multiplies keep the accelerators busy, and prompt length sets the time to the first token.

8.2Fill the KV cache

Each layer stores keys and values for every position so they never have to be recomputed. With compressed attention, a block of tokens shares one entry; DeepSeek‑V4 keeps the positional dimensions in BF16 and the rest in FP8.

Attention & KV mode, as drawn
V4-Pro at 1M: ≈10% of V3.2’s stored KV. CSA selects compressed history; HCA reads heavily compressed summaries; both keep a recent window*

8.3Batched with strangers

A scheduler re-forms the batch at every iteration. Your prefill joins other users’ decode steps whenever cache memory is free, and finished requests leave without waiting for the rest.

09

Think before answering.

On Fable 5.2, thinking is always on. The model writes reasoning tokens through the same decode loop before it writes its answer.

9.1Effort sets the depth

You don’t set a token budget. You set effort, from low to max, and the model decides how much to think. For Fable 5.2, Anthropic suggests starting at high.

Effort, as drawn
16 thinking tokens in the drawing (illustrative; real runs use far more)
Effort levels
low → max
Anthropic docs

9.2Never returned raw

The raw chain of thought never leaves the server. The response carries thinking blocks that are empty by default (display: "omitted") or hold a summary ("summarized"). Thinking is billed the same either way.

thinking: { type: "adaptive", display: "summarized" }

9.3Reasoning picks the tool

Here the model works out that it can’t know today’s weather and should call get_weather. Every reasoning step attends over the KV cache, “ Paris” included.

10

One token per step.

After prefill, generation is a loop: one pass up the tower for each new token, every pass reading the whole KV cache.

10.1Memory-bound

Each step streams the active weights and the cache through memory to produce a single token. That’s why decode speed is measured in tokens per second, and why sparse experts and compressed caches matter so much.

10.2Sample

The model produces a probability distribution over possible next tokens. Sampling selects one token from that distribution, which becomes the next step in the generated reasoning, tool call or answer. The exact sampling policy for Fable 5.2 is controlled by the model provider.

10.3Draft, then verify

A cheap draft proposes the next token or two, and the next pass of the big model checks them in parallel. In the representative design the draft comes from the MTP head*. An accepted draft gives two tokens for one pass. Anthropic doesn’t publish how Claude is served.

Technique
Speculative decoding
Leviathan et al., 2023

10.4“Paris”, again

The model writes a tool call: get_weather with {"city": "Paris"}. Inside JSON the word has no leading space, so it’s a different token ID from “ Paris”; attention copies it from the prompt anyway. The cache grows by one entry per token.

{ "type": "tool_use", "name": "get_weather",
  "input": { "city": "Paris" } }
11

Stream it out.

Token IDs are decoded back into text and sent to your app as server-sent events while generation is still running.

11.1Detokenize

IDs map back to bytes. A partial UTF-8 sequence waits in a buffer until it forms a whole character, so a multi-byte character never arrives split.

11.2Stream

Text and tool input arrive as content_block_delta events over SSE. A single response can run to 128K output tokens.

event: content_block_delta
data: {"delta": {"type": "input_json_delta",
        "partial_json": "{\"city\": \"Par"}}

11.3Stop, with a reason

Generation ends with a stop reason, such as end_turn, max_tokens, refusal, pause_turn when a server-tool loop hits its limit, or, here, tool_use.

Stop reason
"tool_use"
Anthropic docs
12

Call a tool. Continue.

The model can’t check the weather itself. It stops, your code does the work, and the conversation goes back in.

12.1Your code runs the tool

Claude doesn’t execute get_weather; your app does, then appends a tool_result. Treat that result as untrusted input. Server tools such as web search and code execution run on Anthropic’s side instead.

{ "type": "tool_result", "tool_use_id": "toolu_…",
  "content": "{\"temp_c\": 18, \"conditions\": \"clear\"}" }   # illustrative

12.2A new request, a warm prefix

Because the API is stateless, the whole conversation is sent again. The unchanged prefix hits the prompt cache, so only the tool result has to be prefilled.

Prefix cache mode, as drawn
Warm prefix cache hit ($0.20 / MTok): tools + system reused (doubled line); prefill fast-forwards to uncached suffix

12.3The answer

Decoding resumes: “It’s 18 °C and clear in Paris right now.” (illustrative). The reply ends with stop_reason: "end_turn", and “ Paris” reaches your screen.

12.4Long sessions

When a long agent session nears the context limit, server-side compaction (beta) summarizes earlier turns so the loop can keep going.

150K tokens (default)
