Chapter 1 of 6 · Data & tokens

Sources from everywhere

Web pages, code, books, math, and synthetic reasoning traces are gathered into a single stream of raw text.

Pretraining corpus: 33T tokensDeepSeek-V4 paper

Duplicates out, quality in

Copies are hashed and removed so nothing is learned twice. Filters drop low-quality text and personal data, and the mix is rebalanced so no source dominates.

clean_data = balance_mix( filter_pii_and_quality( dedupe_hash(raw_sources) ) )

Byte-pair encoding cuts the sentence

The tokenizer splits text into pieces from a fixed vocabulary. Common words become one token, and in byte-level vocabularies like this one the leading space usually travels with the word, so our token is “ sat”.

Every token becomes an ID

Rare words split into several pieces, each an integer ID. Images take a different road: a vision encoder turns patches into vectors, not IDs.

token_ids = bpe_encode("Architecting") // -> [4182, 287] (illustrative IDs)

Vocabulary: 129,280 tokensDeepSeek-V4-Pro config

Chapter 2 of 6 · Pretraining at scale

Streams rise through the tower

Batches of token sequences flow up through every layer of the model. In training each sequence is processed in parallel, with a mask so no position can peek at the future.

Score the guess, send gradients down

After “The cat”, the model spreads probability over the vocabulary. The loss is the negative log of the probability it gave “ sat”. Gradients travel back down the same layers and Muon, with AdamW for embeddings, the head and norms, updates the weights.

loss = cross_entropy(logits, next_tokens) + mtp_weight * mtp_loss

Bars and loss curve are illustrative.

Sharded across racks, trained in FP8

A model this size is sharded across racks of accelerators using several kinds of parallelism at once, including expert parallelism. DeepSeek-V4 trains in FP8 mixed precision; quantization-aware training later stores the routed experts in FP4 for the released model.

FP8 training · FP4 experts via QAT · Muon + AdamWDeepSeek-V4 paper

Then, a million-token memory

Pretraining stretches the context window in stages, from 4K to 16K to 64K and finally one million tokens, switching on sparse CSA/HCA attention from 64K.

Context: 4K → 16K → 64K → 1M tokensDeepSeek-V4 paper

Chapter 3 of 6 · Post-training & RL

First, specialist SFT and RL

DeepSeek-V4 uses a two-stage post-training pipeline. First, domain specialists (math, code, agentic, instruction) are trained independently via SFT followed by RL with GRPO.

Stage 1: Domain specialists (SFT + GRPO) → Stage 2: On-Policy DistillationDeepSeek-V4 paper

Draw a group of attempts

For one prompt with a checkable answer, the policy, the same tower, samples several attempts. The group of eight here is illustrative.

Grade against the group

Rule verifiers score code and math attempts, while rubric-guided self-judging grades open-ended tasks. Each score is compared with the group’s mean—no separate value model required.

advantage_i = (score_i - mean(scores)) / std(scores)

Distill specialists into one model

Winning attempts reinforce each specialist with a KL anchor to the reference model. Then On-Policy Distillation (OPD) merges all domain specialists into one unified model before the release gate.

update(policy_weights, advantage, kl_penalty); student = on_policy_distill(specialists)

Chapter 4 of 6 · Inside the model

An ID becomes a vector

At the base of the tower, the token ID indexes one row of the embedding table: a lookup, not a calculation. Out comes a vector of 7,168 numbers that enters the 4-stream mHC residual bus.

vector = EMBEDDING_TABLE[token_id] // O(1) array lookup -> float[7168]

Hidden size 7,168 · 4-stream mHC residualDeepSeek-V4-Pro config

Normalize, then look back

RMSNorm rescales a copy of the vector (and Q/KV before core attention). Attention lets “ sat” score earlier tokens while a causal mask hides later ones, with learnable attention sinks so heads can abstain.

scores = causal_mask( (Q_h @ K_h.T) / sqrt(d) ); out_h = softmax_with_sinks(scores) @ V_h

Hybrid CSA + HCA compression

DeepSeek-V4-Pro interleaves Compressed Sparse Attention (CSA: 4× KV compression + Lightning Indexer top-1,024 + 128-tok window) with Heavily Compressed Attention (HCA: 128× dense summaries) and 64-dim decoupled RoPE. Switch the drawing to Inference to watch it fill.

At 1M ctx: 27% FLOPs & 10% KV cache vs V3.2DeepSeek-V4 paper

Merge via mHC hyper-connections

Attention’s output is projected back to 7,168 and mixed across the 4-stream Manifold-Constrained Hyper-Connections (mHC) residual bus, keeping deep signal propagation stable without over-amplifying.

H_stream = mHC_mix(H_stream, linear_project(concat(heads))) // 4-stream residual

The router picks 6 of 384

A router scores 384 routed FP4 experts via sqrt(softplus) and keeps the top 6, while 1 shared expert always runs. That is why only 49B of the 1.6T parameters work on each token.

s = sqrt(softplus(u @ W_router)); top6 = top_k(s + load_bias, k=6); out = shared_ffn(u) + sum(g_j * ffn_j(u))

6 of 384 routed experts (+1 shared) · 49B activeDeepSeek-V4-Pro config

Sixty-one distinct layers

The block repeats 61 times up the tower, each with its own weights. The first 3 use Hash-routed MoE (replacing V3’s dense FFNs), and the rest use learned-router MoE; layers alternate HCA and CSA attention.

61 layers · first 3 Hash-MoE · HCA/CSA interleavedDeepSeek-V4-Pro config

Score the whole vocabulary

At the top, a final RMSNorm and the LM head turn the vector into one score per vocabulary token. What happens to those scores depends on the mode.

logits[0..129279] = final_vec @ LM_HEAD.T // raw unnormalized scores

7,168 → 129,280 logits (+1 MTP layer)DeepSeek-V4-Pro config

Training: loss up top, gradients down

The top output is compared with the real next token, “ on”. The loss flows back down the tower as gradients, and Muon, with AdamW for embeddings, the head and norms, updates the weights. There is no KV cache: the whole sequence runs at once.

loss = cross_entropy(logits, next_token); weights = muon_step(weights, grad(loss))

Inference: the same tower, frozen

Serving uses the identical tower with frozen FP4+FP8 weights. The pass only goes up. Each CSA/HCA layer writes its compressed latent into the KV cache beside it, and the top output goes to a sampler.

Chapter 5 of 6 · Serving a request

Through the gate

The API checks your key, rate limits, and reasoning effort setting (Non-think, Think High, Think Max), screens for abuse, and routes you to a cache-warm replica that encodes messages and tools.

POST /v1/messages { model, messages, tools, reasoning_effort: "high", stream: true }

Stateless APIs re-send history each turn; prefix cache avoids re-prefill2026 frontier APIs

Disaggregated & continuously batched

Modern engines separate Prefill and Decode onto dedicated GPU pools (PD disaggregation), continuously batching requests each iteration and transferring paged KV blocks over NVLink/RDMA.

gpu_batch = active_decode_users + next_prefill_chunk // PD-disaggregated pools

Continuous batching + Prefill-Decode disaggregationOrca 2022 · llm-d 2025

Prefill: read it all at once

The model node opens onto the same tower, now in inference mode. Every prompt token goes up it in one parallel pass. That is compute-bound, and it fills the KV cache, including the entry for “ sat”. Its length sets time-to-first-token.

GB200 dense FP4: 10,000 TFLOPS per GPU (5,000 FP8; 720 PFLOPS NVL72 rack; prefill is compute-bound)NVIDIA GB200 NVL72

Decode: one token per tick

Each new token (first hidden <think> tokens, then the visible reply) streams frozen FP4+FP8 weights and the compressed KV cache from HBM3e—memory-bound—often accelerated by MTP/EAGLE speculative drafting.

GB200 HBM3e: 8.0 TB/s per GPU (576 TB/s NVL72 rack; decode is memory-bound)NVIDIA GB200 NVL72

Sample, check, stream

The sampler drops the unlikely tail and picks a token. Text is detokenized into a buffer, output guardrails check the buffered chunk, and only then is it flushed to you as a server-sent event.

verdict = output_check(buffer); if (verdict.ok) sse_stream.flush(buffer); else cut_stream();

Model card: temperature 1.0, top_p 1.0 for local runsDeepSeek-V4-Pro card

Chapter 6 of 6 · Agents & tool loop

The model stops with a tool call

Instead of more text, generation ends with a structured request, a tool name and arguments, and the stop reason says so.

resp = POST(messages) // stop_reason == "tool_use"

Client-run tools stop generation; hosted tools can execute server-side2026 frontier APIs

Your app (or MCP server) runs it

For client tools, your app or an MCP server executes the call and keeps the result (provider-hosted sandboxes can run built-in code/web tools directly). Always treat tool outputs as untrusted input.

Prompt injection mostly arrives via tool results and documents, not at the gatewayillustrative

A brand-new request

Because the API is stateless, your app sends the whole conversation again: history, the tool call and its result.

resp2 = POST(messages + [tool_call, result])

Prefix cache: prefill only what’s new

The server recognises the unchanged prefix, “ sat” included, and reuses its cached KV entries. Only the new tokens are prefilled, then decoding continues. The loop repeats until the model answers in plain text.

// server: prefix-cache hit, prefill only the new tokens
