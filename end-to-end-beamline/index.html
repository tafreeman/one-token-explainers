Make the data.

Months before your request, text and code are gathered, cleaned and encoded using a fixed vocabulary. Image inputs follow their own visual preprocessing path.

Guess the next token

At every position in every sequence, the tower is asked what comes next. A causal mask lets each position see only earlier tokens, so a whole sequence trains in one parallel pass. After “…the Eiffel Tower is in”, the right answer is “ Paris”. The bars on top are the model’s scores for every vocabulary entry.

loss = −log p(" Paris" | "…the Eiffel Tower is in")

Gradients run back down

The loss is differentiated through the active computation, producing gradients, drawn as copper rings; the optimizer updates trainable weights. This is where the training copy of “ Paris” ends. It survives only as tiny changes spread across the weights. A multi-token-prediction layer adds a second loss for the token after next.

W ← W − η · Muon(∇W) # AdamW for embeddings, head and norms

Spread across a cluster

No single chip holds the model, so layers, experts and data are split across a cluster of accelerators that work in lockstep. Training runs its matrix math in 8-bit floating point. Quantization-aware training then lets the released model store its routed experts in 4 bits, to save memory and bandwidth.

Then, a longer memory

The representative model trains at progressively longer sequence lengths: 4K, 16K, 64K, then 1M tokens. Then, many tries

For a prompt with a checkable answer, the model samples a group of attempts and verifiers grade them: the tests pass, the final answer matches. Each score is compared with the group mean. Above-average attempts (solid) are reinforced, and below-average ones (dashed) are discouraged, so no separate value model is needed.

A_i = (r_i − mean(r)) / (std(r) + ε_std)

Study · the full GRPO objective

J(θ) = E[ 1/G · Σ_i 1/|o_i| · Σ_t ( min( ρ_i,t · A_i , clip(ρ_i,t, 1 − ε, 1 + ε) · A_i ) − β · KL(π_θ ‖ π_ref) ) ] ρ_i,t = π_θ(o_i,t | q, o_i,<t) / π_old(o_i,t | q, o_i,<t) A_i = (r_i − mean(r)) / (std(r) + ε_std) # equal rewards give A_i = 0; ε_std > 0

The ratio ρ compares the policy being trained with the one that sampled the group. Clipping limits the surrogate incentive to change sampled-token probabilities; it is not a hard bound on the policy update. The KL term is the additional penalty in the next step.

An ID becomes a vector

At the base, the token ID selects one row of the embedding table. It is a lookup, not a calculation: out comes a vector of 7,168 numbers, and that vector is what rides up the tower.

x = E[id] # E: 129,280 × 7,168
Hidden size7,168DeepSeek‑V4

One stream, many additions

The vector travels the residual stream, drawn as the steel rod. Each layer reads a normalized copy (RMSNorm), computes something, and adds the result back. DeepSeek‑V4 widens it into four parallel streams, mixed between layers by manifold-constrained hyper-connections (mHC): the rod’s four twisted strands.

x = x + attn(norm(x)); x = x + moe(norm(x)) # one stream, simplified

Study · manifold-constrained hyper-connections

X_l+1 = H_res · X_l + H_postᵀ · F( H_pre · X_l ) # X: 4 streams × 7,168 H_res = SinkhornKnopp(·) # doubly stochastic: rows and columns sum to 1

F is the layer’s attention or MoE block. H_pre reads one input from the four streams, H_post writes the output back across them, and H_res mixes the streams. Because H_res is doubly stochastic, repeated mixing across 61 layers can’t amplify the signal.

Residual streams (hc_mult)4DeepSeek‑V4

Attention looks back

In every layer, “ Paris” forms a query and scores it against the keys of earlier tokens. Thicker arcs mean more weight. The causal mask, the red plate, hides everything after it. 128 heads do this in parallel, each with its own projections, and position enters through rotary encoding (RoPE).

out = softmax( q · Kᵀ / √d + mask ) · V

At a million tokens, look selectively

DeepSeek‑V4 reduces long-context attention work with two compressed branches. Compressed sparse attention (CSA) uses a lightning indexer to select entries; heavily compressed attention (HCA) reads more compressed summaries without that selection step. Both also read a recent window of 128 tokens.

keys = window(128) ∪ top_k( indexer(q), k = 1,024 )

Six experts out of 384

The feed-forward half of each layer is a mixture of experts. A router scores 384 routed experts, sends “ Paris” to the top six, and mixes their outputs by its weights, while one shared expert always runs. That is why only 49B of 1.6T parameters work on any one token. The first few layers route by a fixed hash instead.

y = shared(x) + Σ_{i ∈ selected} g_i · expert_i(x) g_i = 2.5 · s_i / Σ_{j ∈ selected} s_j # s_i = sqrt(softplus(router_i(x))); load-balance bias selects experts only

Score the whole vocabulary

A final RMSNorm and the LM head turn the vector into one score per vocabulary entry, and softmax turns the scores into probabilities. A small multi-token-prediction head, behind it, also drafts the token after next, which serving can use to decode faster.

Prefill, think, decode, stream.

The prompt goes up in one pass. Then the model thinks, writes one token at a time and streams the result.

Stations 7–9 · model, decode, stream

Prefill: process known prompt positions

Prefill processes prompt positions in parallel, often in chunks, while layers remain sequential. It is often compute-bound and builds attention state in the KV cache, the yellow rack. DeepSeek‑V4 stores compressed history alongside recent-token state. Prompt length, caching and serving load all affect time to first token.

KV[0 … n] = prefill(prompt)

KV cache in trainingnonePope ’22

Think before answering

Fable 5.2 keeps adaptive thinking enabled; the model decides whether and how much to reason on a turn. Reasoning tokens use the decode loop, and effort guides token use. Raw reasoning is never returned as readable text: thinking blocks carry an encrypted signature, with readable text omitted by default or summarized on request. Preserve those blocks unchanged during tool loops.

Decode: one token per step

In basic autoregressive decode, each next token needs a forward pass that reads active weights and the cached history selected by attention. Decode is often memory-bound; its bottleneck depends on the workload. The cache is updated, while compressed history and local windows need not add one permanent entry per token. Speculative decoding can verify several draft tokens in one target pass.

logits_t, KV = forward_and_update_cache(token_{t−1}, KV) # cache format depends on attention
