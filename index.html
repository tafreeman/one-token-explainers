Chapter 1 of 6 · Data & tokens

Sources from everywhere

Web pages, code, books, math, and synthetic reasoning traces are gathered into a single stream of raw text.

Pretraining corpus: 33T tokensDeepSeek-V4 paper

Duplicates out, quality in

Deduplication reduces repeated documents. Quality and privacy filters reduce unwanted material, and source weighting controls the data mix. The cleaning pipeline shown is illustrative.

clean_data = balance_mix( filter_pii_and_quality( dedupe_hash(raw_sources) ) )

Byte-pair encoding cuts the sentence

The tokenizer splits text into pieces from a fixed vocabulary. Common words become one token, and in byte-level vocabularies like this one the leading space usually travels with the word, so our token is “ sat”.

Every token becomes an ID

Rare words can split into several pieces, each an integer ID. In vision-language models, image encoders can supply vectors instead of BPE IDs. The DeepSeek-V4-Pro reference here is text-only.

token_ids = bpe_encode("Architecting") // -> [4182, 287] (illustrative IDs)

Vocabulary: 129,280 tokensDeepSeek-V4-Pro config

Chapter 2 of 6 · Pretraining at scale

Streams rise through the tower

Batches of token sequences pass through the layers in order. Within each layer, many sequence positions are processed in parallel, with a causal mask so no position can use future tokens.

Score the guess, send gradients down

After “The cat”, the model spreads probability over the vocabulary. The loss is the negative log of the probability it gave “ sat”. Gradients travel back down the same layers and Muon, with AdamW for embeddings, the head and norms, updates the weights.

loss = cross_entropy(logits, next_tokens) + mtp_weight * mtp_loss

Bars and loss curve are illustrative.

Sharded across racks, trained in FP8

A model this size is sharded across racks of accelerators using several kinds of parallelism at once, including expert parallelism. DeepSeek-V4 trains in FP8 mixed precision; quantization-aware training later stores the routed experts in FP4 for the released model.

FP8 training · FP4 experts via QAT · Muon + AdamWDeepSeek-V4 paper

Then, a million-token memory

Pretraining stretches the context window in stages, from 4K to 16K to 64K and finally one million tokens, switching on sparse CSA/HCA attention from 64K.

Context: 4K → 16K → 64K → 1M tokensDeepSeek-V4 paper

Chapter 3 of 6 · Post-training & RL

First, specialist SFT and RL

DeepSeek-V4 uses a two-stage post-training pipeline. First, domain specialists (math, code, agentic, instruction) are trained independently via SFT followed by RL with GRPO.

Stage 1: Domain specialists (SFT + GRPO) → Stage 2: On-Policy DistillationDeepSeek-V4 paper

Draw a group of attempts

For one prompt with a checkable answer, the policy, the same tower, samples several attempts. The group of eight here is illustrative.

Grade against the group

Rule verifiers score code and math attempts, while rubric-guided self-judging grades open-ended tasks. GRPO compares each score with its group; a small ε_std keeps equal-score groups well-defined, with zero advantage.

advantage_i = (score_i - mean(scores)) / (std(scores) + ε_std)

Distill specialists into one model

Relative rewards guide each specialist’s policy updates. A KL penalty can constrain drift from a reference policy. DeepSeek-V4 then uses On-Policy Distillation (OPD): a student learns from specialist teachers’ output distributions on its own generated trajectories.

update(policy_weights, group_advantage); student = on_policy_distill(specialist_teachers)

Chapter 4 of 6 · Inside the model

4.1–4.4 · Embedding, Hybrid Attention & mHC

4.1An ID becomes a vector

At the base of the tower, the token ID indexes one row of the embedding table: a lookup, not a calculation. Out comes a vector of 7,168 numbers that enters the 4-stream mHC residual bus.

vector = EMBEDDING_TABLE[token_id] // O(1) array lookup -> float[7168]

Hidden size 7,168 · 4-stream mHC residualDeepSeek-V4-Pro config

4.2Normalize, then look back

RMSNorm rescales the attention branch input. DeepSeek-V4 attention reads selected earlier compressed blocks and a recent uncompressed window. A causal mask blocks future information; learnable attention sinks let heads allocate less weight to content.

scores = causal_mask((Q_h @ K_h.T) / sqrt(d_head)); out_h = softmax_with_sink(scores) @ V_h

4.3Hybrid CSA + HCA compression

DeepSeek-V4-Pro interleaves Compressed Sparse Attention (CSA: 4× KV compression + Lightning Indexer top-1,024 + 128-tok window) with Heavily Compressed Attention (HCA: 128× dense summaries) and 64-dim decoupled RoPE. The inference drawing shows the cache filling.

At 1M ctx: 27% FLOPs & 10% KV cache vs V3.2DeepSeek-V4 paper

4.4Merge via mHC hyper-connections

Attention’s output is projected back to 7,168 and mixed across the 4-stream Manifold-Constrained Hyper-Connections (mHC) residual bus, keeping deep signal propagation stable without over-amplifying.

H_stream = mHC_mix(H_stream, linear_project(concat(heads))) // 4-stream residual

4.5–4.7 · Sparse MoE, 61 Layers & LM Head

4.5The router picks 6 of 384

In learned-router layers, sqrt(softplus) affinity scores select 6 of 384 routed FP4 experts, while 1 shared expert always runs. The first 3 layers use hash routing. This sparse design activates about 49B of the model’s 1.6T parameters per token.

s = sqrt(softplus(u @ W_router)); top6 = top_k(s + load_bias, k=6); g = 2.5 * normalize(s[top6]); out = shared_ffn(u) + sum(g_j * ffn_j(u))

6 of 384 routed experts (+1 shared) · 49B activeDeepSeek-V4-Pro config

4.6Sixty-one distinct layers

The block repeats 61 times up the tower, each with its own weights. The first 3 use Hash-routed MoE and the rest use learned routers. The first 2 attention layers use HCA; the remaining layers interleave CSA and HCA.

61 layers · first 3 Hash-MoE · HCA/CSA interleavedDeepSeek-V4-Pro config

4.7Score the whole vocabulary

At the top, a final RMSNorm and the LM head turn the vector into one score per vocabulary token. These scores now go to the sampler.

logits[0..129279] = final_vec @ LM_HEAD.T // raw unnormalized scores

7,168 → 129,280 logits (+1 MTP layer)DeepSeek-V4-Pro config

4.8–4.9 · Frozen Weights, Changing Request State

4.8Weights stay fixed; activations change

The checkpoint stays fixed while “ sat” produces new activations and attention-cache state. No loss, backpropagation or optimizer step runs in this ordinary inference pass. The output scores describe possible continuations, including “ on”.

logits, next_cache = forward(prompt_ids, frozen_weights, cache)

4.9Inference: the same tower, frozen

Serving uses the same model architecture with frozen weights, including FP4 routed experts. The forward pass updates compressed and sliding-window attention state in the KV cache, and the top output goes to a sampler.

The drawing follows frozen-weight inference; serving details depend on the engine.

Chapter 5 of 6 · Serving a request

Through the gate

The API checks credentials, rate limits, and generation settings. Providers or applications can add abuse screening and cache-aware routing. This DeepSeek example uses the Anthropic-compatible Messages format, with thinking enabled and high effort.

POST https://api.deepseek.com/anthropic/v1/messages { model: "deepseek-v4-pro", messages, tools, thinking: { type: "enabled" }, output_config: { effort: "high" }, max_tokens: 4096, stream: true }

This stateless Messages endpoint receives conversation history on each turnDeepSeek API docs

Disaggregated & continuously batched

Continuous batching admits and removes requests between model iterations. Some deployments also separate Prefill and Decode onto dedicated GPU pools (PD disaggregation), transferring cached attention state between them. These are serving choices, not requirements of the model.

prefill_batch = ready_prompt_chunks; decode_batch = active_sequences // separate pools in this example

Continuous batching · optional Prefill-Decode disaggregationOrca 2022 · llm-d

Prefill: process known prompt positions

Prefill processes known prompt positions in parallel within each layer, possibly in chunks. It fills attention-cache state and produces the first output-token scores. It often has higher compute utilization than small-batch decode; scheduling, cache hits and network delays also affect TTFT.

GB200 dense FP4 peak: 10,000 TFLOPS per GPU (5,000 FP8; 720 PFLOPS NVL72 rack; hardware ceiling, not measured V4 speed)NVIDIA GB200 NVL72

Decode: one token per tick

Ordinary decoding advances one token per sequence per model step. Thinking mode can generate reasoning before the reply. Small-batch decode is often limited by memory bandwidth, while batching, context length and communication can change the bottleneck. Speculative decoding may accept several verified tokens at once.

GB200 HBM3e peak: 8.0 TB/s per GPU (576 TB/s NVL72 rack; hardware ceiling)NVIDIA GB200 NVL72

Sample, check, stream

The sampler selects the next token. Supported constrained-decoding modes can enforce JSON schemas; ordinary tool calls still need validation. Detokenization buffers partial characters. A deployment may check buffered output before sending server-sent events.

text = detokenize(next_id); buffer.append(text); // optional output checks, then SSE

Model card: temperature 1.0, top_p 1.0 for local runsDeepSeek-V4-Pro card

Chapter 6 of 6 · Agents & tool loop

The model stops with a tool call

For a client-run tool, the model emits a tool-use block and the Messages response ends with stop_reason: "tool_use". Your application may expose tools discovered from an MCP server; MCP is the host-to-tool protocol, not a separate model execution step.

resp = messages_api(messages) // stop_reason == "tool_use" for a client tool

Client tools return control to the application; hosted tools can run server-sideDeepSeek Messages API · MCP

Your app (or MCP server) runs it

For client tools, your app invokes the implementation, possibly through an MCP server, and collects the result. Provider-hosted tools can execute server-side. Treat tool definitions, retrieved documents and tool results as untrusted input: each can carry indirect prompt injection.

Gateway screening does not remove the need to handle untrusted tool contentMCP security guidance

A brand-new request

For this stateless Messages endpoint, your app sends the conversation again, including the assistant’s complete content and matching tool results. In thinking mode, preserve the required thinking blocks along with the tool-use blocks.

resp2 = messages_api(history_with_tool_use_and_tool_result)

Prefix cache: reuse available state

When a reusable prefix is present in the cache, the server reuses its cached state and prefills the unmatched suffix. DeepSeek-V4 may also recompute a short tail to restore sliding-window state. Cache availability and hit rules depend on the serving system.

// cache hit: reuse available prefix state; prefill suffix and any required tail

A published model architecture, followed through an illustrative training and serving pipeline.

  1. Data & tokens →Text from everywhere, cleaned and cut into IDs; “ sat” is one of 129,280.
  2. Pretraining →33T tokens of next-token guesses in FP8 with Muon and AdamW, gradients flowing back down.

  6. Agents →Return control for client tools, send their results, and reuse available prefix-cache state when eligible.
